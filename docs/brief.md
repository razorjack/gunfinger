(`docs/brief.md`). Nobody will answer questions until morning. Never stop to ask.
When something is ambiguous, take the conservative option, write the decision
down, and continue. Stop only when the Definition of Done is met or every

Every item is tagged:

- **[FIXED]**: the owner's decision. Do not revisit.
- **[DEFAULT]**: follow it unless verification shows it is wrong. If you deviate,

- **[OPEN]**: yours to decide by measurement, using the stated criterion.

## 1. Mission

Gunfinger is a local Rust CLI that identifies tracks from a personal collection
inside DJ mixes. The music is jungle and drum & bass; the most important mixes
are vinyl sets from 1999 to 2002. On turntables pitch and tempo move together
(the record is simply resampled), within about ±8%. The collection will
eventually hold 25,000+ tracks on a NAS.

Unknown audio must stay unknown. A confident wrong identification is worse than
a miss.

This session is a proof of concept with two deliverables:

1. A measured answer: can tracks be found in two real mixes, at the pass bar in
   section 7.7?
2. An elegant seed repository that the real project will grow from.

Out of scope, do not build: configuration system, `doctor`, any database, NAS
scanning, CI, key-locked (pitch-preserved) sets, robustness work for EQ or
blends, timeline polish, TUI. Record them in `docs/roadmap.md` instead.

## 2. What exists at the start [FIXED]

- macOS with Homebrew, `ffmpeg`, `ffprobe` and a Rust toolchain. Network access
  for crates. You may `brew install` or `cargo install` tools; no sudo.
- This file, and `corpus/`: private, copyrighted audio. Treat it as read-only

```text
corpus/
├── library/            reference tracks, scan recursively
│   ├── Artist - Title.mp3 ...     36 files, mostly played in the sets
│   └── extra/ ...                 a few hundred more, nested release folders
└── sets/<set-name>/
    ├── <one audio file>
    └── tracklist.toml             ground truth
```

Facts about the library:

- Formats are mp3, m4a (AAC) and opus. Some files carry embedded cover art.
- Folders also contain junk: `.nfo`, `.sfv`, images, `.cue`, text files, and
  audio renamed to non-audio extensions. Skip by extension, count what you skip.
- Filenames are messy. An asset's identity is its path relative to the library
  root. Do not parse artist or title out of names.
- The same recording often exists as several files (different rips).
- Remixes and VIPs of played tracks are present on purpose as hard negatives.

The two sets have different roles:

- `stakka-skynet-knowledge`: 11 tracks, all referenced. **Development set.**
- `ed-rush-optical-essential-mix`: 31 tracks, 17 referenced, 14 deliberately
  absent; a radio broadcast with speech and jingles. **Held-out test set.**

A set directory without `tracklist.toml` is ignored.

Manifest schema:

```toml
title = "…"
audio = "file name inside the set directory"

[[track]]
position  = 2
artist    = "Bad Company"
title     = "The Nine"
start     = "2:55"                          # M:SS or H:MM:SS, approximate
reference = ["Bad Company - The Nine.mp3"]  # paths relative to corpus/library;
                                            # [] = played, deliberately absent
note      = "optional free text"
```

A track ends where the next begins; the last ends with the file. Neighbouring
tracks overlap around each boundary.

## 4. Engineering baseline

- **[FIXED]** Stable Rust, Edition 2024, `rust-toolchain.toml` with rustfmt and
  clippy, `Cargo.lock` committed.
- **[FIXED]** Synchronous Rust. No async runtime, database, Docker, network
  service, neural model, GPU, SIMD or `unsafe` (forbid it at workspace level).
- **[FIXED]** Gunfinger owns its fingerprinter. No third-party fingerprinting
  crate. Implement from the papers (Wang 2003; Six & Leman 2014; Six 2021) and
  do not copy code from existing implementations.
- **[DEFAULT]** A workspace of three crates, each with a real boundary:
  - `gunfinger-core`: decoding, peaks, hashing, index, matching.
  - `gunfinger`: the CLI.
  - `gunfinger-eval`: development harness (manifests, sweep, scoring).
    The manifest must be unreachable from the first two. Enforce it through
    dependency direction: `eval` depends on `core`, never the reverse.
- **[DEFAULT]** Dependencies: `clap` (derive), `serde`, `serde_json`, `toml`,
  `thiserror`, `miette` in the CLI, an FFT crate, `proptest` where a real
  invariant exists. Anything else must earn its place.
- **[DEFAULT]** `scripts/check.sh` is the quality gate: `cargo fmt --all
--check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo
test --workspace`. Use clippy's default groups plus a curated set of pedantic
  lints; allow a lint with a stated reason when it hurts readability.

## 5. House style [FIXED]

Write idiomatic Rust for a reader with a Rubyist's intolerance of accidental
complexity. This is not Ruby in Rust. Minimise conceptual complexity, not line
count. `AGENTS.md` must carry these rules for future sessions.

- Code reads top to bottom in domain vocabulary, in small functions whose names
  reveal intent. Types carry meaning where they clarify (`AssetId`,
  `FrameIndex`, `SpeedRatio`, `Peak`, `Posting`); no wrappers for ceremony.
- Ownership is obvious. No `clone()` to silence the borrow checker, no lifetime
  gymnastics to save a harmless clone, no reflexive `Arc<Mutex<_>>`, no
  `Box<dyn Trait>`, single-implementation traits or generics without need.
- Enums over boolean flags. `?` and clear `Option`/`Result` flows. No
  `unwrap`/`expect` on production paths, no panics for user or environment
  errors.
- DSP code uses explicit loops that visibly follow the algorithm. Comments
  explain why, the maths, invariants and paper provenance, never syntax.
- Side effects sit at the edges (FFmpeg, files, CLI); the core is pure where
  practical.
- Errors are actionable: what failed, why it matters, what to do.
- Tests optimise for clarity, not DRY.
- Optimise only from measurement.
- No dead code. An experiment that loses is deleted from the tree; its result
  lives in `docs/experiments/`.

## 6. Pipeline

### 6.1 Decoding [FIXED]

Decode with the `ffmpeg` executable through `std::process::Command`, never a
shell string. Stream stdout into Rust.

```text
ffmpeg -nostdin -v error -threads 1 -i <path>
       -map 0:a:0 -vn -sn -dn -ac 1 -ar <rate> -f f32le pipe:1
```

- Set stdin to null, drain stderr concurrently, kill and reap the child on
  error or abort.
- A non-zero exit, or error output with truncated audio, is a failed asset:
  report it, write nothing for it, carry on.
- Support excerpts through `-ss` and `-t`.
- Default extensions, case-insensitive: `mp3, m4a, opus, ogg, flac, wav, aiff`.
- **[DEFAULT]** Skip assets longer than 20 minutes with a warning
  (`--max-track-minutes`); they are mixes or album rips, not tracks.

### 6.2 Peaks [FIXED principle, OPEN parameters]

Mono PCM, then STFT, log magnitude, and two-dimensional local-maximum peak
picking. The stored peaks (frame, bin, magnitude) are the source of truth:
hashes and the index are always derived from them, so hash design can change
without decoding audio again.

- **[OPEN]** Sample rate (start at 8 kHz), window, hop, neighbourhood, density.
- This music is bass-heavy. Check that one band does not monopolise the peaks,
  and spread density across frequency if it does.

Peak store **[DEFAULT]**:

- Directory `work/peaks/`, overridable with `--peaks-dir` and
  `GUNFINGER_PEAKS_DIR`. It will later live on a NAS: sequential reads and
  writes only, atomic write (temporary file, then rename), no mmap.
- Each record is self-describing: format version, front-end profile, source
  path relative to the library root, size, mtime, duration, peaks.
- `index` skips an asset whose record matches path, size, mtime and profile.

### 6.3 Hashing and matching

**Candidate A, speed ladder [DEFAULT, build first].** Index the library once at
native speed with exact hashes from peak pairs: anchor frequency, target
frequency, time delta. Absolute frequency stays in the hash because it makes
hashes distinctive and postings small. Search the query under a ladder of
assumed speed ratios covering 0.92 to 1.08; on the right rung its hashes line
up exactly. Evidence for a track is a set of hits lying on one line
`t_ref = a·t_query + b` that persists over time. The slope gives the speed, and
persistence over tens of seconds separates a played record from chance.

Measure, do not assume:

- hash survival against residual speed error, which sets the ladder step;
- whether a rung is best realised by resampling audio, by a new STFT, or by
  transforming peak coordinates;
- how to tolerate slow pitch rides while a DJ beatmatches.

**Candidate B, invariant hashes [fallback].** A log-frequency front-end with
hashes from peak triplets, using frequency differences in log bins and ratios
of time deltas. These are unchanged by resampling and need one pass, at the
cost of fewer bits per hash and larger postings.

Build A first. Move to B only if A cannot reach the development bar after about
six principled iterations, or its query cost is impractical. Stop at the first
candidate that passes; do not build the second for comparison.

### 6.4 Index [DEFAULT]

In memory, rebuilt from the peak store: postings sorted by hash with an offsets
table, each posting packed as tightly as fidelity allows. Use the layout you
would put on disk, so the size measurements in section 8 are real. Do not build
an on-disk index.

### 6.5 Detections and confidence

`identify` emits detections: asset, start and end in the query, speed ratio,
score, and a `confident` flag. Sub-threshold candidates may be listed
separately.

- **[FIXED]** One frozen confidence rule for every input.
- **[OPEN]** The statistic. It must rest on absolute, sustained, aligned
  evidence compared with a measured null. Do not use the fraction of query
  hashes (blends dilute it) or best-versus-runner-up (duplicate rips defeat it).

### 6.6 Command line [DEFAULT]

```text
gunfinger index <LIBRARY> [--jobs N]
gunfinger identify <AUDIO> --library <LIBRARY> [--start T] [--duration T]
                   [--exclude-from FILE] [--format human|json]
gunfinger stats --library <LIBRARY> [--format human|json]
```

- `--jobs` defaults to available parallelism; `GUNFINGER_JOBS` overrides it.
  One worker handles one file. Use scoped threads; no nested parallelism.
- JSON goes to stdout with a `schema_version` and no ANSI codes. Progress and
  diagnostics go to stderr.
- Human output is a plain aligned table: time span, speed, confidence, asset.
- The index must be restrictable to a subset of assets, for hold-out tests.

## 7. Evaluation protocol [FIXED]

### 7.1 Separation

`gunfinger` and `gunfinger-core` never see a manifest, a set name or a track
title. No per-track, per-set or filename-derived logic anywhere.

### 7.2 Duplicate clusters

Before scanning any set, find files that are the same recording by matching the
library against itself with a deliberately strict criterion. Save the clusters
to `work/reports/duplicate-clusters.json` and summarise them in an experiment.
Clusters depend on library audio alone: never add an asset to a cluster because
of what a set scan returned.

### 7.3 Self-generated speed sweep

`gunfinger-eval` builds a seeded, repeatable test from the library:

- Hold out about 20% of clusters from the index entirely.
- Take 30-second excerpts from at least 60 assets, indexed and held out.
- Resample each (pitch and tempo together) to −8, −5, −3, −1, 0, +1, +3, +5 and
  +8%, and encode lossily.
- Indexed excerpts must return their cluster; held-out excerpts must return
  nothing confident.

Report recall per speed, wrong answers, and speed-estimate error. Diagnostic
bar: at least 95% recall for speeds within ±5%, and zero wrong answers. Do not
start on the sets until the sweep clears it. If a held-out "wrong answer" turns
out to be a duplicate rip, fix the clustering rule and rerun.

### 7.4 Development set

Iterate freely on `stakka-skynet-knowledge`. In addition, for at least three
referenced tracks (seeded choice), exclude the track's whole cluster and
rescan: that slot must produce no confident detection.

Calibrate the confidence rule on the sweep, the development set and the
leave-outs together. Report the margin between the weakest true confident
detection and the strongest false candidate.

### 7.5 Freeze, then test

When the development bar is met and section 8 is done, commit, tag
`poc-freeze-1`, and only then run `ed-rush-optical-essential-mix`. Record the
first-run result verbatim.

If it fails you may diagnose and improve, under these rules:

- Every further evaluation of the test set is appended to
  `docs/experiments/test-set-ledger.md` with what changed and why.
- Changes must be general.
- At most five evaluations of the test set in total. After that, write up.
- The final report states the first-run result and the evaluation count.

### 7.6 Scoring

- Only `confident` detections count.
- A referenced track is **identified** when a confident detection of one of its
  references, or of an asset in the same duplicate cluster, overlaps the window
  from 90 seconds before its start to 90 seconds after the next track's start.
  **[DEFAULT]** tolerance.
- Any other confident detection is a **wrong identification**, including any in
  a slot marked absent.
- Matches credited through a cluster are listed separately for the owner to
  confirm.
- If evidence suggests the ground truth is incomplete, do not edit the manifest
  and do not tune the match away. List it under "for the owner to check". It
  still counts as wrong.

### 7.7 Pass bar

On each set: at least 80% of referenced tracks identified, and zero wrong
identifications. The development set gates progress. The test set gives the
verdict.

## 8. Index size [FIXED rule]

The index must be space-efficient without losing fidelity. Every layout
decision reports bytes per posting and justifies each stored field. Choose the
leanest configuration whose sweep and development results are no worse than the
best.

Measure and report through `gunfinger stats`:

- postings per second of audio, and bytes per posting including the offsets
  table;
- hash-bucket occupancy: mean, 99th percentile, maximum, and the share of
  postings in the fullest 1% of buckets;
- peak-store bytes per second of audio;
- a projection to 25,000 tracks at the measured mean duration.

Evaluate at least: lower density against recall; 4-byte postings against wider
ones; delta or varint coding of posting lists, measured offline on real data.
Record the recommended on-disk design in an ADR for the next session.

## 9. Tests [DEFAULT]

- Unit tests for pure logic: hash packing, peak-store round trip, time parsing,
  manifest validation, scoring.
- Codec tests generate tiny synthetic fixtures with FFmpeg at test time: mp3,
  AAC in m4a, m4a with attached cover art, opus, flac, alac, wav. Assert that
  decoding succeeds, output is mono at the expected rate, duration is within
  tolerance, and artwork is never decoded as audio. Skip with a clear message
  when FFmpeg is missing.
- Corpus evaluations are not part of `cargo test`.
