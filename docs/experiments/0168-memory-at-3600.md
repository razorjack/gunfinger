# 0168: the Linux machine's memory at its rated speed

**Question.** 2026-10-21, between sessions: the Linux machine's four DDR4-3600
modules ran at the JEDEC default of 2133 MT/s (XMP off; `dmidecode -t 17`).
With XMP on (3600 MT/s, both channels), how much faster are the memory and the
search, with and without experiment 0167's change?

**Method.** The same probe (`work/perf-design/claude-fable-5-1-scratch/probe`),
then 0167's four scans of the Stakka mix at NAS scale and the clusters sample
(`clusters --from-peaks --sample 48`, 32 jobs, the index built first), current
code (`work/bin/s35-final`) against 0167's change, machine otherwise idle, one
run each (`work/perf-design/verify/ab.sh`, `clusters.sh`; the 2133 results in
`work/perf-design/verify/2133/`).

| | 2133 MT/s | 3600 MT/s |
|---|--:|--:|
| Sequential read, 2-32 threads | 25.6-27.0 GiB/s | 40.1-46.2 GiB/s |
| Latency, 256 MiB region | 104.6 ns | 81.8 ns |
| Scan search, current code, 32 jobs | 76.7 s | 49.7 s |
| Scan search, current code, 16 jobs | 49.3 s | 47.7 s |
| Scan search, 0167's change, 32 jobs | 38.5 s | 37.9 s |
| Scan search, 0167's change, 16 jobs | 45.7 s | 46.4 s |
| Clusters sample, current code | 210.9 s | 165.1 s |
| Clusters sample, 0167's change | 120.9 s | 118.9 s |

- Every scan report is identical to the 2133 ones apart from `wall_seconds`;
  the clusters samples are byte-identical to each other and to 2133's.
- No machine-check or EDAC error in the kernel log since boot. Four dual-rank
  modules at 3600 were not stress-tested here.
- The 2133 clusters figures are the design agent's runs (0167).

**Conclusion.** The faster memory helps only the runs whose hit buffers spill
out of the L3: the current code at 32 workers (search 35% shorter, clusters
22%). At 16 workers, and with 0167's change at either count, the search time
does not move (within 2%), which supports the reading that it works in cache
and is bound by the cores. 0167's change gives more than the memory setting:
37.9 s against 49.7 s at 32 workers, 119 s against 165 s for the clusters.
